# imp_test 功能设计计划

## Summary

新增 `imp_test.cpp` 和 `seml/imp/{lib.h,types.h,data.h,operation.h}`，复用现有 JSON 配置结构，采用 `smash_test` 式连续多波时间线：所有 waves 串成一局，前波红眼/白眼和小鬼会继续被后续操作影响。该功能统计小鬼是否被炮/灰烬影响、未受灰烬影响的小鬼比例，以及小鬼对各保护植物造成的伤害；保护植物只用于伤害统计，不决定巨人出怪行，空地漏出同样视为不可接受风险。

## Key Changes

命令行接口：

```powershell
dest/bin/imp_test.exe -f config.json [-o imp_test] [-r 10000] [-cd]
```

巨人类型来自 JSON `setting.types`，SEML 中由 `types:白红` / `types:garg giga` 生成；缺省时默认同时测试白眼 `23` 和红眼 `32`。程序按巨人类型分别跑完整连续时间线，避免修改模拟器核心来追踪小鬼父对象。

JSON 输入沿用现有 `Config`：`setting.scene`、`setting.protect`、`setting.types`、`waves[].iceTimes`、`waves[].waveLength`、`waves[].actions`。

出怪不再依赖保护植物行：每波、每个参与测试的巨人类型仍生成 5 只巨人；生成时不传指定行，直接调用模拟器原生 `zombie_factory.create(type)`，让模拟器根据 `scene_type`、`spawn.wave` 和僵尸类型自行选择合法行。计划和实现不新增 `get_imp_garg_rows(scene_type)`，也不手工维护 day/night/pool/fog/roof 的可出怪行规则；所有行统计以后续模拟器实际生成的 `z.row` 为准。

保护植物只用于伤害统计，`protect` 允许为空。有保护植物时，全部种下并逐个统计伤害，允许同一路多个保护植物，且设置极高 HP 和 `ignore_garg_smash=true`，避免巨人砸击干扰小鬼伤害统计。没有保护植物时，仍正常输出漏出摘要表和详细表；小鬼炮伤表保留 `总和` 行，数值为 0。

不设置 `disable_garg_throw_imp`，让巨人按原生逻辑半血投小鬼；设置 `w.scene.ignore_game_over = true`，避免空地漏出或进家导致整局提前停止，从而影响后续波次和操作统计。

## Implementation Details

`operation.h` 采用连续 `base_tick` 模型：每波起点生成 5 个指定类型巨人，创建巨人时不传指定行，由 `zombie_factory.create(type)` 原生选行；冰、炮、卡片、垫材动作按 `base_tick + action.time` 排入同一时间线。每次初始化或重置场景后设置 `stop_spawn=true`、按命令行设置 `disable_cob_delay`、设置 `ignore_game_over=true`；其中冰只参与游戏模拟，不作为操作影响记录。

详细操作列只记录炮、灰烬：

- `Cob` 记为灰烬操作，使用发炮返回的 uuid 匹配小鬼 `hit_by_ash`。
- 樱桃、辣椒、倭瓜、核蘑记为灰烬操作。
- `iceTimes` 仍按现有逻辑种冰并影响游戏状态，但不出现在详细操作列中。
- 垫材照常执行，但不出现在详细操作列。

每只小鬼记录：出生波数、巨人类型、出生 tick、行号、是否受每个炮/灰烬操作影响、是否“存活”、对各保护植物的伤害。

“存活”定义为：从出生到测试结束没有被任何炮/灰烬命中。

操作状态输出：

- 灰烬/炮：`HIT` 或 `MISS`；小鬼未出生或已结束则留空。

小鬼伤害归因：为保证归因准确，在 `seml/imp` 中搬运并封装模拟器里与小鬼啃食相关的判定逻辑，在每次 `w.update()` 前预判本帧实际会造成啃食伤害的小鬼和目标保护植物，并把每个命中的小鬼按原生规则记录 4 点伤害。预判逻辑需要与 `zombie_system::update_eating()`、`update_eating_plants()`、`zombie_base::find_target()` 和 `can_attack_plant()` 对小鬼的相关分支保持一致，包括小鬼飞行/落地不啃食、冰冻/黄油不更新、慢速时啃食节奏变化、啃食节奏 `time_since_spawn % op == 0`、攻击框重叠阈值、泳池水路限制、梯子/大蒜/魅惑等会改变啃食结果的条件。保护植物 HP 差分只作为调试校验：每帧预判伤害总量应等于对应保护植物实际 HP 下降量；若不一致，将该帧计入归因异常并在调试输出或断言中暴露。

## Output Format

一个 CSV 内输出三个表，整体风格靠近 `smash_test` 的摘要 + 明细表。

### 1. 存活摘要表

格式严格贴近 `smash_test` 的摘要表。列按出生波数展开，表头使用 `w1,w2,w3...`，行先输出总和，再按模拟器实际产生过潜在小鬼样本的行集合输出各路漏出率，行号升序排列。红眼和白眼不分块、不分行；所有通过 `setting.types` 参与测试的巨人类型合并统计到同一张表中：

```csv
单波漏出率,w1,w2,w3,
总和,4.90%,0.00%,0.00%,
1路,1.22%,0.00%,0.00%,
2路,1.16%,0.00%,0.00%,
5路,1.27%,0.00%,0.00%,
6路,1.25%,0.00%,0.00%,
```

总和漏出率 = 该出生波中所有参与测试巨人类型的漏出小鬼数 / 该出生波中所有参与测试巨人类型的潜在小鬼数。各路漏出率 = 该出生波、该行中所有参与测试巨人类型的漏出小鬼数 / 该出生波中所有参与测试巨人类型的潜在小鬼数；因此各路漏出率相加应等于总和漏出率。

其中漏出小鬼指实际投出且未受任何炮/灰烬命中的小鬼；潜在小鬼数指该出生波、该行、该巨人类型实际生成的巨人数之和。若白眼或红眼在投出小鬼前被击杀，则该巨人仍计入潜在小鬼数，但不会产生漏出小鬼。即使某一路没有保护植物，该路漏出仍进入漏出摘要表，因为空地漏出代表小鬼可能直接进家，是不可接受风险。

### 2. 小鬼炮伤表

格式贴近漏出摘要表和 `smash_test` 摘要表。列按出生波数展开，表头使用 `w1,w2,w3...`，行先输出总和，再按保护植物输出有限炮伤：

```csv
小鬼炮伤,w1,w2,w3,
总和,12.5,0,0,
1路5炮,3.0,0,0,
2路5炮,2.5,0,0,
5路5炮,3.4,0,0,
6路5炮,3.6,0,0,
```

炮伤摘要表只统计非漏出小鬼造成的有限伤害。单元格 = 对应出生波中，所有参与测试巨人类型的小鬼对该保护植物造成的有限啃食伤害总和 / repeat。这里的分母固定为 repeat，与 `explode_test` 的单波期望损伤口径一致；不是实际投出小鬼数、潜在小鬼数、命中小鬼数或产生伤害的小鬼数。

漏出小鬼不进入炮伤摘要表；它们的风险由“单波漏出率”表表达，并在详细表中以 `INF` 表示。`总和` 行为该出生波下所有保护植物有限伤害的合计，应该等于各保护植物行之和。若 `protect` 为空，小鬼炮伤表仍输出 `总和` 行，所有波次值为 0。

### 3. 详细表

group by：`出生波数 + 巨人类型 + 小鬼结局 + 每个炮/灰烬操作状态`。

输出字段：

```csv
出生波数,巨人类型,小鬼结局,总数,<各路总数>,<各保护植物受伤害>,<各炮/灰烬操作状态>
```

`小鬼结局` 固定为三类：

- `未投出`：父巨人在投出小鬼前死亡，该潜在小鬼没有实际生成。
- `漏出`：小鬼实际投出，且没有受到任何炮/灰烬 `HIT`。
- `拦截`：小鬼实际投出，且至少受到一次炮/灰烬 `HIT`。

字段计算方式：

- `总数`：该分组内的潜在小鬼样本数。
- `<各路总数>`：该分组内各行的潜在小鬼样本数，行号使用父巨人/小鬼所在行。
- `<各保护植物受伤害>`：保留该分组的原始伤害，不除以 `repeat`，不除以小鬼数。
- `未投出` 行的各保护植物伤害输出 `0`。
- `漏出` 行的各保护植物伤害统一输出 `INF`，表示不可接受风险，不参与有限炮伤摘要表；即使漏出来自没有保护植物的空地，也按脑伤/进家风险处理，不按保护植物同路性拆分 `INF`。
- `拦截` 行的各保护植物伤害输出该分组内所有小鬼对该保护植物造成的真实有限啃食伤害原始累计值。

摘要表必须能从详细表复算：漏出摘要表的分母为该出生波所有详细表行的 `总数` 之和，分子为 `小鬼结局 = 漏出` 的 `总数` 之和；炮伤摘要表从所有 `小鬼结局 = 拦截` 的详细表行汇总有限伤害后再除以 `repeat`。

操作状态列只记录炮/灰烬，不记录冰。列按实际时间顺序排列，可沿用 `[wN] 操作描述` 的表头风格。`HIT` 表示该炮/灰烬命中过这组小鬼；`MISS` 表示操作发生时小鬼已投出且尚未死亡，但没有命中；空值表示操作发生时小鬼未投出、已死亡，或该行为 `未投出` 结局。

示例：

```csv
出生波数,巨人类型,小鬼结局,总数,1路,2路,5路,6路,1路5炮,2路5炮,5路5炮,6路5炮,[w1] 359炮,[w2] 225灰烬
1,白眼,未投出,120,30,30,30,30,0,0,0,0,,
1,白眼,漏出,49,12,11,13,13,INF,INF,INF,INF,MISS,MISS
1,白眼,拦截,9831,2458,2459,2457,2457,148,96,132,124,HIT,
```

## Test Plan

- 编译验证：确认 Makefile 自动编译新增 `imp_test.cpp`，并生成 `dest/bin/imp_test.exe`。
- 单波无拦截：配置只让巨人投出小鬼，不设置炮/灰烬；预期存活率为 100%，详细表伤害为 `INF`。
- 单波炮拦截：配置用炮命中投出后小鬼；预期对应操作为 `HIT`，存活率下降，炮伤表出现有限伤害。
- 冰测试：配置冰影响小鬼但不灰烬命中；预期冰会影响后续模拟结果，但不出现在详细表操作列中，存活率仍按未受灰烬影响计入存活。
- 连续多波测试：第一波投出小鬼，第二波操作命中；预期第一波小鬼在详细表中被第二波操作标记影响。
- 局部保护植物测试：`protect` 只覆盖部分行；预期漏出摘要表输出模拟器实际出怪过的行，而不是只输出保护植物行。
- 空保护植物测试：`protect` 为空；预期程序不报错，漏出摘要表和详细表正常输出，小鬼炮伤表 `总和` 为 0。
- 泳池/雾夜出怪测试：不手工指定行；预期模拟器不会在水路生成红/白眼，漏出摘要表只呈现实际生成过潜在样本的行。
- 空地漏出测试：没有保护植物的行漏出；预期详细表漏出行伤害列输出 `INF`，且 `ignore_game_over=true` 后后续波次仍继续模拟。
- 多保护植物测试：同一路和不同路多个保护位均输出独立伤害列，存活摘要按模拟器实际出怪行聚合。
- 归因校验测试：构造单只小鬼啃食单株保护植物、同帧多只小鬼啃食同株植物、冰减速后啃食三类场景；预期预判伤害与 HP 差分完全一致。

## Assumptions

- “存活率”按拦截可靠性定义为“未受炮/灰烬影响率”，不是测试结束时对象仍在场上的字面存活率。
- 默认同时测试白眼和红眼；用户可用 SEML `types:红` 或 `types:白` 限定。
- “所有陆地都要出巨人”采用现有测试风格的随机候选含义：每波 5 只巨人由模拟器原生行选择逻辑分布到合法陆地行，而不是强制每条陆地行各出一只。
- 行统计以模拟器实际生成结果为准；计划和实现不重复维护场景合法行规则。
- 空地漏出按不可接受失败处理，保留 `INF` 表达，不尝试按保护植物同路性拆分 `INF`。
- 不修改模拟器核心字段；父巨人类型通过“按巨人类型分开运行”保证准确。
